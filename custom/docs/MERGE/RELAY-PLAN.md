# 中继接入计划（手机互通 · 第一性）

> 日期：2026-11-21　状态：计划（未实施）
> 前提：中继机 `124.221.231.213` 已有 frps / EasyTier relay / Geyser；公网 19132 已验证可达；
> 新端口 21000 在机内转发通过、公网被**云安全组**挡住。
> 目标：手机在**任意网络**扫码一次即可进房；PC 侧现有联机行为不变。

## 0. 第一性：这份方案只允许三样东西

| 层 | 职责 | 复杂度 |
|---|---|---|
| 中继 | 端口池 + UDP 转发（把 `公网:2100x` 转到房主 `虚拟IP:19132`） | 一个守护进程，无 JVM |
| 协议 | 房间记录里多一个字段：`Relay = "ip:port"` | 一个字段 + 签名规范化 |
| 客户端 | 开基岩桥时申请端口，把二维码里的地址换成中继地址 | 一个 HTTP 调用 + 一处地址来源 |

**刻意不做**：中继端 Geyser（每房一个 JVM，机器只剩 666 MB，放不下）、房主装 frpc（EasyTier 已够）、
Java 走中继（PC 继续走 EasyTier）、账号体系（房间签名已够）。

## 1. 数据流

```
房主 PCL Pro                        中继 124.221.231.213                     手机
 建房 + 对局域网开放
 启动基岩桥 (Geyser:19132)
        │  POST /v1/relay {roomId, target=10.x.x.x:19132}
        ├──────────────────────────────▶ 房间索引确认 roomId 存在且未过期
        │                               从 21000-21099 分配端口，起转发
        │ ◀────────────────────────────  { port: 21001 }
 二维码 = 124.221.231.213:21001
        │                                                      扫码 → 添加服务器 → 进服
        │                               UDP 21001 ⇄ 10.x.x.x:19132（Geyser）      │
        └──────────────────────────────────────────────────────────────────────┘
 离开房间 → DELETE /v1/relay {roomId} → 回收端口
```

## 2. 里程碑

### M0 · 客户端最小改动（可立刻做，不依赖中继）
1. `ProPhoneService.TryStart` 成功后：若 `Config.Link.PhoneRelayEnabled` 且拿到了房间码 →
   `POST {LinkRelayUrl}/v1/relay`，body `{roomId, target}`；失败只写日志，退回局域网地址。
2. 新增配置：`LinkRelayUrl`（默认 `http://124.221.231.213:8089`）、`PhoneRelayEnabled`（默认 false，灰度）。
3. 二维码/复制文本的地址来源改成：有中继用中继，否则用 `LanIp()`（顺带修掉现在写死
   `10.114.51.41` 的 bug）。
4. 停桥/退出房间 → `DELETE /v1/relay`；心跳 60 s 续租（复用 `RoomHeartbeatService` 的节奏）。
- 验收：中继未上线时，行为与现在完全一致（只是地址从虚拟 IP 变成局域网 IP）；上线后二维码变中继地址。

### M1 · 中继转发守护（需要安全组放行 UDP 21000-21099）
1. `relayd.py`：`POST /v1/relay` 分配端口并 fork 转发线程；`DELETE` 回收；`GET /v1/relay/{id}` 状态；
   端口池空闲 5 分钟自动回收；单房限 1 端口。
2. `systemd` 单元 `pclpro-relay.service`，`Restart=always`，内存上限 128 MB，日志到 journal。
3. 权威判定：`POST` 时向本机房间索引（8088/8089）查 `roomId` 是否存在、未过期；查不到就 403。
   不在转发器里做密码学——签名由索引服务负责。
- 验收：机内 `127.0.0.1:21001` ping 通；放行后公网 ping 通；`DELETE` 后端口立即不可达。

### M2 · 手机真机验收（依赖 M1）
1. 房主建房 → 扫码 → 手机用**蜂窝网络**（关 Wi-Fi）进服。
2. 两台手机同时进；房主退出 → 端口回收、手机掉线且重连失败（预期）。
3. 断网 30 s 恢复：转发不断、端口不换（UDP 无连接，天然容忍）。
- 验收：手机侧只做「扫码 → 在 Minecraft 里点一次」，无输入。

### M3 · 收尾
1. 文档：`docs\MERGE\RELAY-PROTOCOL.md`（接口、端口池、回收规则）+ 本计划的状态更新。
2. `release\verify.ps1` 里加一条：中继 `/health` 可达（可选项，失败不阻断发版）。
3. 观察一周：端口泄漏、并发峰值、带宽曲线；再决定是否把 `PhoneRelayEnabled` 转默认开。

## 3. 关键决策（需要拍板）

| # | 问题 | 建议 |
|---|---|---|
| 1 | 云安全组放行哪些端口 | UDP 21000-21099（100 房并发足够） |
| 2 | 房间索引放哪 | 复用 `mcp-api`（8088）加两张表；不新起 .NET 服务（内存不够） |
| 3 | 转发器语言 | Python3（机器已有，零安装）；单进程 asyncio，100 房约 30 MB |
| 4 | 默认开关 | 先默认关、灰度验证；稳定后默认开 |
| 5 | 计费/限制 | 每房 1 端口、单 IP 最多 2 房、空闲 5 分钟回收；够防误用 |

## 4. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 房主上行窄（家宽 3-8 Mbps） | 手机卡顿 | 二维码/状态里显示「中继延迟」；文档写清人数建议 |
| 端口被扫、被白嫖 | 带宽被占 | 必须带有效 roomId 才转发；单 IP 限制；空闲回收 |
| 中继抖动 | 全员掉线 | 客户端降级到局域网地址重试（M0 已保留回退路径） |
| 安全组未放行 | M1 卡住 | 唯一阻塞项，需控制台操作 |
| 内存余量 666 MB | 守护进程 OOM 连累 MC 服 | 转发器 `MemoryMax=128M`；不跑 JVM |

| M0 | 客户端 + 配置 + 二维码地址修复 | 0.5 天 |
| M1 | relayd + systemd + 索引校验 | 0.5 天 |

## 6. 回滚

- 客户端：`PhoneRelayEnabled=false` 即回到纯局域网；无数据迁移。
- 中继：`systemctl stop pclpro-relay` 即停；端口全部失效，不影响 Geyser/frps/两个 MC 服。
