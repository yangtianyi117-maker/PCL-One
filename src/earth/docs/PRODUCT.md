# PCL Earth · 产品定义（第一性）

## 1. 命题

Minecraft 的最小构成只有五件事：

| 要素 | 默认形态 | 「世界地图型」要改的那一件 |
|---|---|---|
| 世界数据 | 随机种子生成 | **换成真实地球地理** |
| 服务端规则 | 原版生存 | 领地、国家、战争、经济 |
| 身份 | 账号 | Java 正版 / 离线 / 基岩 Floodgate |
| 入口 | 启动器 → 选版本 → 选服务器 | **启动即进同一个世界** |
| 社交 | 服务器列表 | 国家、城镇、外交 |

「世界地图型」不是新游戏，而是**把世界从随机种子换成真实地理**；其余四件必须围绕它重设，否则地图只是一张好看的地形图。

## 2. 四条不变量

1. **单世界、永不重置。** 所有玩家共享同一张地球；没有赛季、没有换图。
2. **地理即关卡。** 坐标能对应现实地点；距离就是成本；边界就是国际。
3. **双端同世界。** PC Java 与手机 Bedrock 进入同一张地图、同一份存档。
4. **入口最短。** 双击 → 进服 ≤ 3 次点击；不让玩家选版本、选实例、选服务器。

## 3. 由不变量推出的硬约束

- **地图比例是单向门**：1 格 = 多少米，决定「能不能认出家乡」，也决定磁盘与上传成本。上线后不能改，只能开新世界。
- **地图许可是前置条件**：世界文件必须私有，不能进客户端包、不能给玩家下载；否则产品不成立。
- **服务端必须能回滚**：单世界意味着一次坏档就是产品事故；备份与恢复演练是功能，不是运维附属品。
- **入口必须数据化**：不修改 `PCLPro.exe`，只改 `servers.json`、`PCL.ini`、版本 JSON、`servers.dat` 这些公开数据面。

## 4. 产品边界（非目标）

- 不做「又一个启动器」：不抢 PCL/HMCL 的定位。
- 不做 1:1 地球：1:1 需要 CubicChunks 一类的客户端/服务端改造，且基岩端无法互通。
- 不做客户端 mod 生态：只带地图/性能类客户端 mod。
- 不卖数值：不卖资源、不卖领地、不卖战斗力；如接受赞助，只做外观/队列。

## 5. 方案选择（为什么买地图）

| 方案 | 时间 | 成本 | 风险 | 结论 |
|---|---|---|---|---|
| EarthMC Full Earth 2026 1:1000 Vanilla | 1 天 | $10 | 许可限制（不可分发世界） | **选** |
| 自建生成管线（Terra / WorldPainter / 自研） | 3–5 天+ | 0 | 质量、时间、版本兼容 | 备选（Plan B） |
| EarthMC 1:543 | 1 天 | $20 + 120 GB | 上传/磁盘 4× | 上线前可换，需 ≥300 GB |
| 1:217 | — | 423 GB | 不现实 | 不做 |

理由：地图是成熟商品，规则与入口才是差异化；把时间花在「让玩家愿意留下来」而不是「证明自己能生成地形」。

## 6. 成功标准

1. 新玩家从双击到出生点 ≤ 3 次点击。
2. 6 个城市校验点误差 ≤ 1 区块；出生点（伊斯坦布尔）在陆地上。
3. Java 放方块，Bedrock 能看到（同一世界）。
4. Towny 建镇/建国/宣战/停战全流程可跑通。
5. 20 人在线 TPS ≥ 19.5。
6. 备份 → 删除 → 恢复演练 ≤ 30 分钟。
7. 客户端 ZIP 不含任何世界文件（`region/`、`level.dat`、`.mca`）。
8. 许可与署名文件齐全。

## 7. 架构

```
PC:   PCLPro.exe -> versions/Earth-26.3-Fabric.json (quickPlay) -> Java 25565
手机: Minecraft Bedrock -> Geyser 19132 -> 同一 Paper 世界
控制: /pclpro/servers.json -> PCL 联机页卡片
地图: BlueMap 8100（默认仅内网；公网需地图方书面许可）
```
